# Tier-0 size ladder (published artifacts), 2026-09-22

Measured by `scripts/fetch_artifacts.py --sdk all` from the published artifacts only: Maven Central AARs
(`com.github.backtrace-labs.backtrace-android:backtrace-library`), the GitHub Release XCFramework archives of
backtrace-cocoa (`Archive_XCFrameworks_<version>.tar.gz`) and the OpenUPM tarballs of `io.backtrace.unity`.
No build and no device is involved, so every number is exact (`sampleKind: exact`) and reproducible by anyone.

How to read: each column is a release, each cell is the artifact byte count with the change versus the previous
column. Cross-checks: the AAR bytes equal the `Content-Length` served by Maven Central (7,031,209 for 3.14.0,
6,750,439 for 3.10.6, 6,557,495 for 3.8.4). `n/a` means the artifact layout of that release does not contain that
path (for example the iOS slices were laid out differently before 3.15.1).

Observations worth following up in the timing lanes:

- Android: the AAR grew 7.2 % from 3.8.4 to 3.14.0; almost all of it is `classes.jar` (+33 %, the shaded JSON
  library since 3.11.0) and the arm64/armeabi native libraries (+3.2 % in 3.10.6). Nothing changed between 3.13.0
  and 3.14.0 on the native side, so the 3.14.0 startup work is not visible in size and must come from the init lane.
- Apple: the device slice of `Backtrace.framework` grew 41 % in 2.2.0 (1.13 MB to 1.60 MB); `CrashReporter`
  is unchanged since 2.1.0. The release archive shrank 38 % in 2.1.0 because the debug symbols layout changed.
- Unity: the package doubled in 3.15.1 because the iOS device and simulator XCFrameworks (including the static
  CrashReporter) are now bundled; the macOS plugin tripled in 3.17.0 with the universal bundle. Android natives are
  flat across the ladder.
